NodeFable Tutorial

A complete guide to building branching narrative games with the NodeFable canvas.

Getting Started

NodeFable is a visual tool for creating branching narrative games — interactive stories where the reader's choices determine the plot. You build your story as a node graph: each node is a passage of text, and connections between nodes represent choices the reader can make.

The editor is divided into three main areas: Variables (left), the graph canvas (center), and the passage inspector (right).

Tip: Start by adding a few nodes and connecting them to see how the graph works. You can always rearrange nodes by dragging them.

Interface Overview

Header Toolbar

The top bar contains buttons for the main project actions:

  • + Add Node — creates a new story passage.
  • Import Node — opens a modal to paste a JSON node object and add it to the canvas. Useful for copying nodes between projects.
  • + Add Group — creates a new node group with a portal node on the canvas. See Groups & Portal Nodes.
  • Save Project — opens the save dialog (or quick-saves if already named).
  • Load Project — opens the load dialog.
  • Export Game — auto-saves your project and downloads a playable ZIP of your story.
  • Preview Game — auto-saves your project, then opens a live preview of the exported game in a new tab. The preview is served directly from the server so you can test changes quickly.
  • Validate — checks for dead-end nodes (no outgoing choices) and orphan nodes (no incoming connections), highlighted with colored borders on the canvas.
  • Tutorial — opens this guide in a new tab.

Search Bar

A search input in the header toolbar lets you filter nodes by title or slug. As you type, matching nodes are highlighted with a blue glow, while non-matching nodes are dimmed. Press Escape or clear the input to reset the filter.

Left Panel — Variables & Asset Tree

The left panel has two sections. At the top, Global Variables — define variables (integers, floats, strings, booleans) that persist across all passages and track player stats, flags, or inventory. See the Variables section.

Below the variables, the Asset Tree shows all uploaded assets organized in a collapsible folder tree. Each file displays a thumbnail preview and its copyable directive syntax. Click any asset to copy its {img: url} (image) or {video: url} (video) syntax to your clipboard, then paste it into your passage content. See the Asset Tree section.

Center — Graph Canvas, Markdown Editor & Asset Explorer

The center panel has three tabs, switched by the tab bar at the top:

  • Graph Editor — the visual node canvas where you build story structure.
  • Markdown Editor — a full-page textarea for writing the currently selected node's passage content.
  • Asset Explorer — a file manager for browsing, uploading, organizing, and deleting project assets in folders. See the Asset Explorer section.

The formatting toolbar buttons (B, I, H, etc.) live in the right sidebar, not in the center tab. Select a node, switch to the Markdown tab to write, and use the toolbar in the sidebar to insert formatting.

Right Panel — Passage Inspector

When a node is selected, this panel shows its properties: the title, a markdown formatting toolbar, the choices linked from this node (with prerequisite and mutation fields), and the actions that can modify variables when the passage is read. Click Save Passage to persist edits.

Navigating the Canvas

Panning

Click and drag on the empty canvas background (between nodes) to pan the view. This lets you navigate large node graphs. Zoom out first if you need to see the whole story at a glance.

Zooming

Hold the Ctrl key and scroll with the mouse wheel to zoom in and out. The canvas zooms from the top-left corner. Zoom range: 0.15× (far out) to 2.0× (close up).

Dot Grid

The canvas has a subtle dot-grid background to help you align nodes visually. The grid pattern remains fixed as you pan (it does not scroll with the nodes).

Dragging Nodes

Click and hold any node to drag it to a new position. All connection lines update in real time.

Undo & Redo

The editor tracks changes for undo/redo. Use Ctrl+Z to undo and Ctrl+Shift+Z or Ctrl+Y to redo. The undo history is limited to the last 50 snapshots and is cleared when loading a new project.

Tip: Use zoom + pan together to manage large stories. Zoom out to see the big picture, zoom in to work on details.

Adding & Managing Nodes

Adding a Node

Click the + Add Node button in the top toolbar. A new node appears at a random position on the canvas. Each node is automatically given a unique slug based on its title (e.g., the_dark_forest). Slugs are used to create stable links between nodes — renaming a node's title never changes its slug, so existing connections remain valid.

Start Node

The first node displayed when the game starts is marked as the start node. In the right sidebar, check Set as start node to mark a node as the starting passage. A green START badge appears on the node in the canvas. Only one node can be the start — toggling it on another node automatically removes it from the previous one. If no node is explicitly marked, the first non-Side-Panel node in the project data is used.

Editing the Node ID (Slug)

When you select a node, the Node ID (slug) field appears in the right panel below the title. You can manually edit the slug to a custom value (lowercase, underscores, no spaces). When the field loses focus, the editor checks that the slug is unique — if another node already uses that slug, an error message appears and you must choose a different one.

Changing a slug automatically updates all references across the project: choices, connections, and on-enter redirects that pointed to the old slug are updated to the new one. This is safe to do at any time.

Selecting a Node

Click a node on the canvas to select it. The inspector panel on the right shows the node's content and settings. Click the empty canvas area to deselect.

Double-Clicking a Node

Double-click a node on the canvas to open its passage editor and automatically switch to the Markdown Editor tab. This is the fastest way to start writing or editing a passage's content.

Node Overlay Buttons

Hover over a node to reveal its action buttons above it:

  • Edit () — selects the node and opens its passage editor in the sidebar.
  • Delete () — removes the node and all its connections (with confirmation).
  • Link () — enters linking mode to create a connection to another node.

Importing a Node

Click the Import Node button in the toolbar to open the import modal. Paste a JSON object with at least an id field (e.g., copied from another project), then click Import. The node is added to the canvas at a random position. Invalid JSON or missing required fields show an error message.

Deleting a Node

You can delete a node in two ways:

  • Click the button on the node overlay.
  • Select the node and click Delete Node in the inspector panel (right sidebar).

Both methods prompt for confirmation before deleting. Deletion removes all connections to and from the node.

Dead-End & Orphan Detection

After any structural change (adding/removing nodes or connections), the editor highlights problematic nodes:

  • Dead-end nodes — nodes with no outgoing choices or actions. They get a red border. A dead-end ending passage is valid, but unexpected dead-ends may confuse players.
  • Orphan nodes — nodes that no other node links to. They get a gold dashed border. Unless they are reachable via an on-enter redirect, orphans are inaccessible.

Click the Validate button in the toolbar to manually trigger detection. Detection also runs automatically after every node or connection change.

The Side Panel Node

Every project automatically has a node with slug side_panel and title "Side Panel". Its content is rendered in the sidebar of the exported game (e.g., for a player stats panel, inventory, or story log). You can edit its content like any other node. See the Side Panel Node section for details.

Groups & Portal Nodes

Groups let you organize your story into named collections (e.g., chapters, acts, or scenes). Each group is represented by a portal node on the canvas — a dimmed, dashed-border node showing the group label and node count. Only one group's nodes are loaded at a time (plus the side_panel), keeping the canvas uncluttered for large projects.

Creating a Group

  1. Click + Add Group in the toolbar.
  2. A new group is created with an auto-generated ID (e.g., chapter_1) and a portal node appears on the canvas.
  3. Click the portal node to open the group editor in the right sidebar, where you can edit the group label and ID.

New nodes are unassigned by default. To add a node to a group, select the node and choose a group from the Group dropdown in the passage editor.

Loading a Group

Click a portal node and use one of these methods to load its group:

  • Load Group button in the group editor — replaces the portal with the actual nodes on the canvas.
  • Right-click the portal → Load Group.
  • Move to Group (right-click) — unloads all other groups and loads the selected one.

When a group is loaded, its nodes appear at their saved positions. Large groups are loaded in chunks with a progress indicator for smooth performance.

Collapsing a Group

To collapse a group's nodes back into a portal node:

  • Click the up-arrow button (⬆) on any grouped node's top-left corner.
  • Right-click any node in the group → Collapse Group.

Collapsing stores the nodes' content and positions so they can be restored exactly when the group is loaded again. All connections to nodes in other groups are preserved as dashed blue portal output lines on the portal node.

Deleting a Group

Right-click a portal node and select Delete Group. This removes the group manifest entry and portal node from the canvas. It does not delete the individual node data files on disk.

Portal Output Lines

When a group is collapsed but other loaded nodes have connections pointing into it, dashed blue SVG lines are drawn from the source node to the portal's input circles. This makes it visually clear that connections still exist through collapsed groups.

Right-Click Context Menu

Right-clicking a node on the graph canvas shows a context menu with quick actions:

  • On portal nodes: Load Group, Move to Group, Delete Group.
  • On normal nodes: Collapse Group, Delete Node.

The context menu does not appear for the Side Panel node.

Linking Passages (Choices)

To create a choice that leads from one passage to another, you need to link two nodes.

How to Link

  1. Hover over the source node (the passage the reader is currently reading).
  2. Click the (Link) button that appears on the overlay.
  3. The editor enters linking mode:
    • The cursor changes to a copy icon.
    • All nodes get a dashed orange outline.
    • Node overlay buttons are hidden.
  4. Click the target node to complete the link.

Cancelling Linking Mode

Click the same node you started from or click the empty canvas to cancel linking without creating a connection.

What Happens When You Link

When a connection is created:

  • A line appears on the canvas connecting the two nodes.
  • A choice card appears in the source node's passage editor (right sidebar).
  • A markdown link like [Target Title](node:target_slug) is inserted into the source node's passage content.

In the exported game, this link renders as a clickable inline choice that takes the reader to the target passage. You can edit the display text (the [text] part) to change what the reader sees.

Choice Cards in the Sidebar

Each connection is represented as a choice card in the right panel, showing:

  • Target node name (green, with slug).
  • Link text — auto-synced from the [text] in your passage markdown.
  • Remove button to delete the connection.
  • Prerequisite input — an optional condition (JS expression) for the choice to appear.
  • Mutation input — an optional variable change when the choice is taken.

Choice Text Syncing

The link text displayed on the choice card is automatically synced from your markdown content. When you edit the [text] in the passage content and save, the choice card updates. When you create a connection, the link text is set to the target node's title.

Removing a Link

Click the Remove button on a choice card. This:

  • Removes the visual connection line from the canvas.
  • Deletes the associated [text](node:slug) markdown link from the passage content.
  • Cleans up the internal connection data.

Editing Content

Tab-Based Workflow

The editor uses a two-tab layout for content editing:

  • Graph Editor tab (default) — shows the node canvas. Use this to add, link, and arrange nodes.
  • Markdown Editor tab — shows a full-page textarea with the selected node's passage content.

The formatting toolbar (Bold, Italic, etc.) is located in the right sidebar, not in the center tab. To write content: (1) select or double-click a node, (2) switch to the Markdown Editor tab, (3) write your story text, (4) use the toolbar buttons in the right sidebar to insert formatting.

Title

The Title input in the right sidebar sets the node's display name. Titles can contain spaces and special characters. The title is used in choice links (as the default link text) and in the exported game's navigation. Changing the title does not change the node's slug, so existing links remain valid.

Saving Changes

After editing any field (title, content, choices, actions), click Save Passage in the right sidebar. The passage content textarea auto-saves when it loses focus (e.g., clicking elsewhere on the page, switching tabs, or selecting a different node). Content is also auto-saved when you switch between the Graph and Markdown editor tabs, so you won't lose work if you forget to save manually. The title, slug, and other fields are saved when you click Save Passage.

Images

To add an image to your passage, you can either upload directly or use the Image Catalog of already-uploaded assets:

Upload a New Image

  1. Save your project first — the project directory must exist on the server to store the image file.
  2. Click the (Image) button in the formatting toolbar.
  3. A native file picker opens. Select an image file from your computer.
  4. The image is uploaded to the project's assets/ folder and a {img: url} directive is inserted at the cursor.

Insert from the Image Catalog

After uploading, your images appear in the Image Catalog in the left panel. Click any asset there to copy its directive syntax, then paste it into your passage content. See the Image Catalog section for details.

Images render in the exported game with max-width: 100%.

Custom Dimensions

Specify a custom width and/or height with comma-separated options (spaces around = are fine): 

{img: /api/assets/My%20Journey/Alex.jpeg, w=200}
{img: /api/assets/My%20Journey/banner.jpeg, w=800, h=200}
{img: /api/assets/My%20Journey/divider.jpeg, h=50}

Use w= for width and h= for height, separated by a comma. Omit either to let the browser auto-calculate based on the image's aspect ratio. alt= sets accessibility text. The target is everything before the first comma, so spaces in filenames are preserved; the target and alt cannot contain ,, }, or ".

Note: If you haven't saved the project yet, the image upload button will remind you. Save once, then upload.

Video Player

Embed video with {video: url, options}. Video files (mp4, webm, ogg, mov) upload through the asset explorer like images, and clicking one in the asset tree copies the {video: url} directive. 

{video: /api/assets/My%20Journey/rain.mp4}
{video: /api/assets/My%20Journey/rain.mp4, w=480, h=270}
{video: /api/assets/My%20Journey/intro.webm, autoplay=false, mute}

The player always shows controls. Options: autoplay (default true), repeat (loop, default true), mute (default false) as bare flags or key=false, plus w=/h= pixel sizes. Browsers block audible autoplay, so pass mute for reliable ambient autoplay, or autoplay=false to wait for a click. Recommended formats: video/mp4 (H.264/AAC) and video/webm (VP9/Opus).

Node Links (Choices)

When you link two nodes, a node link is automatically inserted: 

[Go to the Forest](node:the_dark_forest)

In the exported game this renders as a clickable inline link. The node: URL scheme is reserved — do not change it manually.

Inline Action Links

The (Action) button inserts an action entry into the node (not just a link). After adding the action and setting its text in the right sidebar, a link like [Search Room](action:a0) is placed in the content. Action links use the action: URL scheme — do not change it manually. See the Actions section.

Variable Interpolation

Reference a variable's current value in passage content using the {var:state.name} syntax: 

Your health is {var:state.player_health}.

In the exported game, this renders as "Your health is 100." (or whatever the current value is). If the variable doesn't exist, the literal {var:state.player_health} is shown.

Important distinction: There are two different {...} syntaxes with different rules:

  • Display interpolation — {var:state.name} — used for showing values in text.
  • Conditional blocks — {if: condition}...{endif} — must use state. prefix in the condition, used for controlling what text appears.

Dialogue

Dialogue blocks give character speech a distinct visual style, separated from the rest of the passage content. Use the {dialogue:} tag with an optional speaker image and name.

Basic Syntax

{dialogue:}Hello world!{enddialogue}

Renders as a styled block with no image or name — just the dialogue text.

With Speaker Name

{dialogue: Bob}Hi there!{enddialogue}

The name appears centered below where the avatar would be.

With Speaker Image

Use standard markdown image syntax inside the opening tag: 

{dialogue: {img: assets/char.png}}Hello!{enddialogue}

With Image and Name

Separate the image and name with a comma: 

{dialogue: {img: assets/char.png}, Bob}Hey, how are you?{enddialogue}

Inline Content

The dialogue body supports all inline markdown — bold, italic, images, choices, actions, and {var:state.name} interpolation: 

{dialogue: Sarah}I've got **{var:state.gold}** gold pieces. Want to trade?{enddialogue}

Image Paths

Use the same image paths as you would in passage content. In the exported game, these are rewritten to local assets/ paths automatically. Use the asset tree to quickly copy image markdown syntax.

Variables

Variables let your story respond to the reader's choices. Define them in the left panel before using them in passages, prerequisites, and mutations.

Adding a Variable

  1. Click + Add Variable in the left panel.
  2. Enter a name (e.g., player_health, has_sword).
  3. Select a type: int, float, String, or bool.
  4. Enter an initial value (must match the selected type).
  5. Click Add.
Important — String values: do NOT wrap them in quotes. Enter the raw text value directly. For example, to set a variable player_name to the value Alex, just type Alex into the initial value field — not "Alex" or 'Alex'. The editor stores it as a raw string automatically. If you add quotes, they become part of the value, and your story would display "Alex" (with literal quote marks) instead of Alex.
Important — Boolean values: enter true or false (lowercase). The editor accepts variations like TRUE, True, or 1 for true, and FALSE, False, or 0 for false.

Editing a Variable

Click anywhere on a variable's name, type, or value in the list to edit it. The variable is removed from the list and the + Add Variable form appears pre-filled with its name, type, and value. Make your changes and click Save Changes to re-add it.

  • The original variable is deleted immediately when you click it — clicking Cancel restores it unchanged.
  • If you edit a different variable while the form is open, the first one is restored automatically before the new one is loaded.

Deleting a Variable

Click the button on any variable in the list to remove it. There is no confirmation — the variable is deleted immediately.

Caution: Deleting a variable cannot be undone (use the edit click instead to modify a variable safely). If a variable is deleted and referenced in passage text, prerequisites, or mutations, those references will fail silently at runtime.

Using Variables in Text

Your health is {var:state.player_health}.
You have {var:state.gold} gold pieces.

Variables in curly braces are replaced with their current values at game runtime.

Variables in Prerequisites & Mutations

Use variables to gate choices and modify state:

  • Prerequisite — a JS expression that must be true for a choice to appear. Example: state.player_health > 0 means the choice only shows if health is above zero.
  • Mutation — a JS statement that runs when the choice is taken or action is triggered. Example: state.player_health = -10 subtracts 10 from health.

All JS expressions must prefix variable names with state. — this is how the game engine accesses the current game state at runtime.

Supported Operators

  • Comparison: ==, !=, >, <, >=, <=
  • Arithmetic: = value (assignment), = +N (increment), = -N (decrement)
Tip: Variable names are case-sensitive. Use snake_case for consistency. Boolean variables work well for flags: has_key = true, door_unlocked = false.

Image Catalog & Asset Tree

The Image Catalog appears in the left panel below the variables list once your project has been saved and contains uploaded image assets. It provides a visual gallery of every image you've uploaded, with a shortcut to insert them into your passage content. Assets are organized in a folder tree for easy navigation.

Opening the Catalog

The catalog is automatically visible whenever the current project has uploaded assets. If you don't see it, save the project first, then upload at least one image. After uploading assets, the tree appears with folders and files.

Asset Tree Structure

The left panel shows a recursive folder tree. Each folder has:

  • A toggle triangle (▶) to expand/collapse and view its children.
  • Inline action buttons for creating subfolders and uploading files into that folder.

Files display a thumbnail preview (for images) and the copyable directive syntax ({img: url} for images, {video: url} for videos). Hover over a file to reveal a delete button. Click any file to copy its directive syntax to your clipboard — the border flashes green to confirm.

Inserting Images via Toolbar

You can also upload and insert images directly from the markdown toolbar:

  1. Make sure the project is saved (the project directory must exist on the server).
  2. Position the cursor in the passage content where you want the image.
  3. Click the (Image) button in the formatting toolbar.
  4. A native file picker opens — select an image file from your computer.
  5. The file is uploaded to the project's assets/ folder and a markdown image tag is inserted at the cursor position.
  6. The asset tree refreshes automatically to show the new asset.
Note: If you haven't saved the project yet, the image upload button will remind you. Save once, then upload.

Image Display in Game

Images render in the exported game with max-width: 100% and auto-height, so they scale to fit the passage width on any screen size. For custom dimensions, add comma-separated options inside the directive, e.g. {img: url.png, w=200, h=300} (see Markdown Reference).

Tip: Use the asset tree to quickly browse all your assets and copy their markdown syntax with a single click — much faster than re-uploading or typing the URL manually. Use folders to organize character portraits, backgrounds, UI elements, and other asset types.

Asset Explorer

The Asset Explorer is a full file manager available as the third tab in the center panel. It provides grid-based browsing and management of all project assets with folder support, upload, rename, delete, copy, and paste operations.

Opening the Asset Explorer

Click the Asset Explorer tab next to the Graph Editor and Markdown Editor tabs. The explorer loads the project's asset tree and shows the current folder contents in a grid.

File Operations

The toolbar at the top of the explorer provides these actions:

  • + New Folder — creates a subfolder in the current directory.
  • ↑ Upload — upload one or more files to the current directory.
  • ✏ Rename — rename the selected item (only enabled when exactly one item is selected).
  • 🗑 Delete — permanently delete selected items (supports recursive folder deletion).
  • 📋 Copy — copy selected paths to the clipboard.
  • ✂ Cut — cut selected paths to the clipboard (for moving).
  • 📌 Paste — paste clipboard contents into the current folder (supports both copy and move).

Navigation & Selection

  • Double-click a folder to navigate into it.
  • Click the breadcrumb path segments to navigate up.
  • Ctrl+Click to toggle selection of multiple items.
  • Click empty space in the grid to deselect all.

The toolbar buttons automatically enable/disable based on the current selection. The status shows how many items are selected.

File Thumbnails

Image files (PNG, JPG, JPEG, GIF, SVG, WebP, BMP) show a thumbnail preview. Other file types show a generic document icon. File sizes are displayed in B, KB, or MB as appropriate.

Actions

Actions are structured variable operations that run when a passage is displayed or when the reader clicks an action link. Unlike choice mutations (single text formulas), actions support multiple condition-mutation pairs for complex multi-variable updates.

Creating an Action

  1. Select a node to open its passage editor.
  2. Scroll to the Actions section in the right panel.
  3. Click + Add Action.
  4. Enter an action name in the text input (e.g., "Take Damage").
  5. Click Update to save the action.

Condition-Mutation Pairs

Each action contains one or more pairs. Each pair has:

  • Condition (optional) — a JS expression. If provided, the mutation only fires when the condition is true. Prefix variables with state. (e.g., state.has_key == false).
  • Mutation (required) — a JS statement like state.player_health = -10. Prefix variables with state. and use notify("message") for custom notifications.

When an action is triggered (via an action link or on enter), every pair whose condition is met (or has no condition) executes its mutation. Add multiple pairs with + Add pair and remove individual pairs with the button. Use Remove to delete the entire action, or Update to save changes.

When Actions Are Disabled

If all pairs have conditions and none are met, the action link is disabled (grayed out) in the exported game. At least one pair must have a met condition (or have no condition) for the action to be clickable.

Action Links in Content

To place an action inline in your passage text:

  1. Position the cursor where you want the action link.
  2. Click the button in the formatting toolbar. This adds a new action entry.
  3. In the Actions section of the sidebar, set the action's display text and configure its pairs.
  4. Click Update to save.

The action link renders as a clickable link in the exported game.

Example: An action named "Search the Room" might have:
• Pair 1: condition state.has_key == false → mutation state.has_key = true
• Pair 2: (no condition) → mutation state.turns = +1
This gives the key if the player doesn't already have one, and always increments the turn counter.

Form Elements

Form elements let players input data directly into the story — typing text, toggling checkboxes, or selecting radio options. Each element is bound to a story variable and updates it automatically. Form elements render as native HTML inputs in the exported game.

TextField

Syntax: {textfield: state.var, hint, commit_mode}

Renders a text input field bound to state.var.

PartRequiredDescription
state.varYesThe story variable to read from and write to
hintNoPlaceholder text shown when the field is empty (grayed out)
commit_modeNoControls when the variable updates: live, blur, or onEnterKey (default)

Commit Modes

ModeBehavior
liveUpdates state.var on every keystroke
blurUpdates when the field loses focus
onEnterKeyUpdates when the player presses Enter (default)

Examples

What is your name? {textfield: state.player_name, Enter your name, blur}

Enter your age: {textfield: state.age, , onEnterKey}
Note: No notification toasts fire on textfield changes, even in live mode.

CheckBox

Syntax: {checkbox: state.var, value}

Renders a checkbox. When value is omitted, clicking toggles state.var as a boolean. When value is provided, checking sets state.var = value; unchecking resets the variable based on its type.

PartRequiredDescription
state.varYesThe story variable to bind to
valueNoIf set, checking sets state.var = value; unchecking resets to type default

Type-Aware Reset on Uncheck

Variable typeReset value
booleanfalse
number0
string"" (empty string)

Examples

{checkbox: state.has_sword} Has Sword            ← toggles true/false

{checkbox: state.occupation, farmer} Farmer      ← sets state.occupation = "farmer"
{checkbox: state.occupation, blacksmith} Blacksmith

Text after the checkbox tag renders as regular passage content — it is not part of the checkbox syntax. Write your label or description as normal text following the {checkbox:...} tag.

Radio Button Groups

Syntax: {radiogroup}...{endradiogroup} wrapping {radiobutton: state.var, value}

Only one radio button per group can be selected. Group membership is determined by the {radiogroup}...{endradiogroup} wrapper. Selecting a radio button immediately updates the variable and re-renders the side panel (HUD).

ElementDescription
{radiogroup}Opens a radio button group
{radiobutton: state.var, value}A single radio option; text after the tag is the label
{endradiogroup}Closes the group

Example

Choose your class:
{radiogroup}
{radiobutton: state.class, warrior} Warrior
{radiobutton: state.class, mage} Mage
{radiobutton: state.class, rogue} Rogue
{endradiogroup}

Text after each {radiobutton:...} tag is rendered as regular passage content (can include bold, links, images, etc.) — it is not part of the radio syntax. The radio group is displayed as a bordered container with stacked options.

TextArea

Syntax: {textarea: state.var, hint, commit_mode, rows}

Renders a multi-line text input. Because Enter inserts a newline, the default commit mode is blur — live updates on every keystroke.

PartRequiredDescription
state.varYesThe story variable to bind to
hintNoPlaceholder text
commit_modeNolive or blur (default)
rowsNoVisible height in lines; default 3
 
Tell your story: {textarea: state.bio, What happened?, blur}

Number

Syntax: {number: state.var, min, max, step}

Renders a numeric stepper. The value updates live and is stored as a JS Number. Clearing the field keeps the previous value (no number → "" type flip). 

Enter your age: {number: state.age, 1, 150}

Dropdown

Syntax: {dropdown: state.var, opt1, opt2, ...}

Renders a select dropdown; each comma-separated param becomes an option (value and label are the same text — options cannot contain commas). The option matching the variable is preselected; declare the variable with the desired default so it starts selected. 

Choose your class: {dropdown: state.class, warrior, mage, rogue}
Tip: Form elements can be placed anywhere in passage text — including inside the Side Panel node for persistent HUD inputs like character naming or stat toggles.

Including Other Passages

Include splices another passage's text into the current passage at render time with {include: slug}. Reuse a shared footer, a welcome preamble, or any prose you want in several places without copy-pasting.

The tag is matched case-insensitively (write it lowercase). The included text is processed like any other markup, so {var:}, {if:}, loops, images, and nested includes all work inside it: 

The inn is quiet tonight.

{include: inn_description}

{include: tavern_menu}

Choices and actions from the included passage become real, clickable links in the host passage — mutations, prerequisites, and disabled-state handling all apply. The host's own choices/actions come first, then included ones in textual order (innermost includes first). An included passage's On Enter hook does not run.

  • Unknown slug: if no passage matches, {include: missing} renders literally so you notice.
  • Circular includes are your responsibility. A safety counter stops expansion after 100 splices per render and shows a one-time Include limit exceeded. toast.
  • Inside {init}: text mutations apply, but the included choices/actions are dropped (init output is suppressed anyway).
  • Reusable: each splice is independent — the same passage can be included in many places.

On Enter Redirect

The On Enter feature automatically redirects the player to another node when they enter a specific passage. Use this for urgent scenes, triggered events, or conditional story beats that shouldn't require the player to click a link.

How to Use

  1. Select a node on the canvas.
  2. In the right panel, scroll to the On Enter section.
  3. Check Enable auto-redirect when entering this node.
  4. Choose the target node to redirect to from the dropdown.
  5. Optionally set a condition — the redirect only fires if this JS expression is true. Prefix variables with state. (e.g., state.rent_overdue == true).
  6. Optionally set a mutation — a JS statement that runs before the redirect.

Examples

// Redirect to rent confrontation if overdue
Condition: state.rent_overdue == true && !state._visited.rent_confrontation
Target: rent_confrontation
Mutation: state.rent_overdue = false

// Redirect to Maya encounter in the afternoon
Condition: state.maya_affection > 20 && state.time_of_day == "afternoon"
Target: maya_park_encounter
Mutation: state.maya_encounter_triggered = true
Tip: The redirect is checked every time the node renders. If the condition is no longer true on subsequent visits, the node displays normally. Use state._visited.<slug> to limit one-time redirects. Use a mutation to set a visited flag if you want the redirect to fire only once.

Multiple Redirects via Markdown

The On Enter panel only supports one redirect per node. For multiple conditional redirects, use {if: condition}{redirect:slug}{endif} (with optional {elseif:} chains) or standalone {redirect:slug} for unconditional redirects: 

{if: state.femininity >= 5}{set: state.femininity += 1}{redirect:dream_gender5}{endif}

Conditions evaluate left-to-right, first match wins. You can include {set: } mutations inside the block. Text-based redirects run before the legacy On Enter field.

How the Game Works

The exported game is a fully self-contained HTML file with no external dependencies. Here's how it behaves at runtime:

Passage Rendering

When a passage is displayed, the game engine:

  • Resolves conditionals ({if:}/{elseif:}/{else}/{endif}) and removes failed branches.
  • Checks text-based redirects ({redirect:slug}) — navigates immediately if found (executing mutations first).
  • Checks legacy on-enter redirect: if configured and the condition is met, the player is sent to the target node.
  • Executes inline mutations ({set:}) and strips all remaining directives.
  • Converts the passage text to HTML (random values, images, links, waits, variable interpolation, formatting).
  • Evaluates all prerequisites: choice links whose conditions aren't met get a disabled class.
  • Evaluates action conditions: action links with no satisfied pairs are disabled.
  • Marks the node as visited in state._visited.<slug>.

Clicking Links

  • Choice links — click to navigate to the target passage. The choice's mutation runs before navigating.
  • Action links — click to run the action's condition-mutation pairs. The current passage re-renders with updated values.
  • Disabled links (grayed out) are not clickable.

Inline Action Links

The exported game renders action links inline in the passage text. When clicked, the action's condition-mutation pairs are evaluated: pairs with no condition always fire; pairs with a condition fire only if the condition is true. After all pairs are processed, the current passage re-renders to reflect updated variable values.

Variable Interpolation

Any {var:state.name} in your passage text is replaced with the variable's current value. If the variable doesn't exist, the original {var:state.name} placeholder is shown literally.

Conditional Content

You can show or hide parts of your passage text based on game state using conditional blocks. This is different from prerequisites — conditional blocks control what text is visible within a single passage, while prerequisites control whether an entire choice link appears. Conditional blocks use state. prefix in their conditions — see the examples below.

Syntax

{if: state.player_health > 50}
You feel strong and healthy.
{else}
You are wounded and weary.
{endif}

How It Works

  • The condition is a JavaScript expression evaluated against the game state. All variables must be prefixed with state. (e.g., {if: state.has_key == true}).
  • {elseif: condition} — additional branches evaluated in order. First truthy branch wins.
  • The {else} branch is optional. Omit it to show nothing when all conditions fail.
  • Nesting is supported — you can put {if: ...} blocks inside other conditional blocks.

Conditional Redirects

You can also use {if: condition}{redirect:slug}{endif} inside your text to auto-navigate to another node when a condition is true. This supports multiple conditional redirects per node — conditions evaluate left-to-right, first match wins. You can use {elseif:} for chained conditions. The redirect block is stripped from the displayed text when no condition matches. You can include {set: } mutations inside the block: 

{if: state.femininity >= 5}{set: state.femininity += 1}{redirect:dream_gender5}{endif}
{if: state.femininity >= 1}{redirect:dream_gender1}{endif}

Text-based redirects are checked before the legacy On Enter field, giving you more flexibility than the single redirect in the panel.

Examples

{if: state.gold >= 100}
You have enough gold to buy the sword.
A magic sword gleams in the shop window.
{elseif: state.gold >= 50}
You don't have enough for the sword, but you spot a decent dagger.
{else}
You only have {var:state.gold} gold pieces. The sword costs 100.
{endif}
{if: state.has_map == true}
You consult your map and find a hidden path.
{else}
The forest stretches in every direction. You're lost.
{endif}

One-Time Setup: {init}

Use {init}...{endinit} to run one-time setup when the player enters a passage. Mutations inside the block run once per fresh entry, and the block itself produces no visible output — great for preparing arrays, counters, or defaults that the rest of the passage reads while re-rendering: 

{init}{set: state.items = ["sword", "shield"]}{set: temp.i = 0}{endinit}
{while: temp.i < state.items.size}{var: state.items[temp.i]} {set: temp.i += 1}{endwhile}

Re-renders of the same passage (after a mutation, without leaving it) do not re-run {init}; the setup only applies on a fresh entry. Use temp for scratch counters — it is never saved and is discarded when you leave the passage.

Loops: {while:}, {do}, {for:}

Repeat blocks of text. {while: cond}...{endwhile} runs 0+ times, {do}...{while: cond} runs 1+ times, and {for: init; cond; update}...{endfor} is the C-style loop: 

{for: temp.i = 0; temp.i < 3; temp.i += 1}{var: temp.i}{endfor}

Renders as 012. {break} exits the innermost loop, {continue} skips to the next iteration, and every loop stops after 1000 iterations as a safety guard.

Two different {...} syntaxes — do not confuse them:
  • Display interpolation — {var:state.name} — use this inside your story text to show a variable's current value. Example: You have {var:state.gold} gold. renders as "You have 200 gold."
  • Conditional blocks — {if: condition}...{elseif:}...{else}...{endif} — must use state. prefix on variables inside the condition expression. The {else} branch is optional. Nesting and chained {elseif:} are supported.
Tip: Conditional blocks are powerful for creating responsive, dynamic passages that change based on the player's choices. Combine them with variables for rich storytelling.

Stat Notifications

When a mutation changes a numeric variable (like health, money, or affection), the engine automatically displays a toast notification at the bottom of the screen. This gives immediate feedback so the player always knows how their choices affected their stats.

Auto-Detection

The engine compares variable values before and after every mutation. Any numeric change is shown as a notification: 

Energy   -10
Gold     -3
Maya Affection  +5

Variable names are automatically formatted from snake_case to Title Case for display. The day variable is excluded from notifications.

Custom Notifications with notify()

You can trigger custom narrative notifications directly in mutation strings using the notify() function: 

// In a choice or action mutation:
state.has_key = true; notify("You found a rusty key under the mat.")

Custom messages appear in the same toast area and auto-dismiss after 2.5 seconds.

Tip: Use notify() for story-important reveals ("The door creaks open...") and rely on auto-detection for stat changes.

Save & Load in Exported Games

The exported game automatically saves progress to your browser's localStorage after every choice or action. If you close the browser or refresh the page, the game restores your state — including all variables, visited flags, and your current passage.

How It Works

  • Auto-save: After every navigation and action, the current game state (variables, current node, visited flags) is saved to localStorage.
  • Auto-restore: When the page loads, the game checks for a saved state. If found and it matches the same project, it restores your progress and shows a "Game restored from save." toast.
  • Manual save slots: The exported game provides 5 manual save slots plus the auto-save slot. Click the Save/Load button (top-right) to open the save manager. Each slot shows the node title and timestamp. You can Save (or Overwrite), Load, and Delete individual slots.
  • New Game: Click the New Game button to clear all saves and restart fresh.

Important Notes

  • Saves are stored per project name and per browser. Different projects don't interfere.
  • Clearing your browser's site data or localStorage will erase your save.
  • The saved state includes all variables (money, energy, etc.) but does not include the story data itself — the story must still load from the embedded JSON.
Note: Save data is stored in the browser and may be affected by private browsing mode or storage limits. The save persists as long as the browser data remains intact.

In the Exported Game

The content is rendered using the same markdown engine as regular passages (with variable interpolation, images, etc.).

Inline Mutations

Inline mutations let you execute JavaScript directly inside passage text using the {set: expression} syntax. The expression is evaluated in the game state context, so you can assign variables and call notify().

Syntax

The time is {set: state.time_text = "Morning"}.
The sun rises over the horizon. Time: {var:state.time_text}

Examples

  • {set: state.greeting = "Hello"} — string assignment
  • {set: state.hp -= 10} — arithmetic expression
  • {set: state.has_key = true} — boolean assignment
  • {set: state.gold += 50} — numeric increment

Use the temp namespace for throwaway values ({set: temp.i = 0}) — it works in every expression context, is never saved, and is discarded when you leave the passage. {unset: state.x} / {unset: temp.x} delete a variable; {unset: temp} clears all scratch values.

How It Works

Inline mutations execute during the directive pass (processDirectives), before HTML escaping, variable interpolation, and link rendering. This means you can set a variable and immediately reference it via {var:state.x} in the same passage.

Caveats

  • The expression is any valid JS statement(s) — use state.varname = value for assignments.
  • Inline mutations run every time the passage renders, including during side panel refresh. Avoid side effects that should fire only once unless you guard them with a condition.
  • For complex multi-statement logic, use a choice mutation or action mutation instead.
Tip: Combine inline mutations with {var:state.x} interpolation for dynamic content that updates based on calculations or expressions — all without needing separate choice/action entries.

Time Transitions (Wait Sequences)

Wait sequences let you create timed animations where content fades in, stays visible, then fades out — perfect for dream sequences, flashbacks, cutscenes, or dramatic reveals. Each {wait:N,fade:M}...{endwait} block is a single item. Multiple blocks run sequentially.

Syntax

{wait:800}
{img: /api/assets/dream1.jpeg}

A strange feeling washes over me...

{img: /api/assets/dream2.jpeg}
{endwait}

The {wait:N} marker starts a wait block where N is the visible duration in milliseconds. The content between {wait:N} and {endwait} fades in, stays visible for N ms, then fades out.

Configurable Fade Duration

{wait:2000,fade:800}
The world blurs around me...

Everything goes dark...
{endwait}

Use {wait:N,fade:M} to set a custom fade duration M (in milliseconds). If omitted, fade defaults to 500ms. Total duration per block: fade + N + fade (fade in, visible, fade out).

Behavior

  • Multiple wait blocks run sequentially — one after the other.
  • Content before the first {wait:N} is visible immediately.
  • Content after the final {endwait} remains hidden until all sequences finish, then fades in with an opacity transition.
  • Each block is a single item: the entire content fades in as one piece.
  • Conditional blocks ({if:}...{endif}) are processed before wait blocks, so you can use conditions to control which sequences play.
  • Markdown syntax (images, bold, italic, links) works inside wait blocks.
  • Variable interpolation ({var:state.x}) works inside wait blocks.

Navigation During Sequences

If the player clicks a choice link or action link during a running wait sequence, the sequence is immediately cancelled and the next passage renders normally.

Per-Item Timeline

PhaseDurationDescription
Fade inM msContent smoothly appears
VisibleN msContent stays fully visible
Fade outM msContent smoothly disappears

Example: Dream Sequence

My eyes grow heavy...

{wait:1500,fade:600}
{img: /api/assets/forest_memory.jpeg}
I remember walking through the ancient woods...

{img: /api/assets/faces.jpeg}
Familiar faces I can't quite name...

{img: /api/assets/door.jpeg}
A door slams shut — I jolt awake.
{endwait}

I sit up in bed, heart pounding.
The dream is already fading.

In this example: all three images and text appear together (600ms fade in), stay visible for 1.5 seconds, then fade out (600ms). After the sequence finishes, the "I sit up in bed..." text appears.

Tip: Use shorter durations ({wait:200}) for rapid flicker effects and longer durations ({wait:3000}) for slow, dramatic reveals. A fade of 300–500 works well for most cases.

Troubleshooting

Preview opens a blank page

Make sure your project has at least one node (other than the Side Panel) and that a start node is marked (or the first node in the project acts as the start). If the preview still shows nothing, check the browser console (F12 → Console tab) for error messages.

Image upload fails

You must save your project at least once before uploading images. The project directory must exist on the server to store asset files. Supported formats: JPEG, PNG, GIF, WebP.

Connections not appearing on load

When loading a project, all node connections are restored in a second pass after node creation. If some connections are missing, the project file may be corrupted or the target node slug may have changed. Check the browser console for warnings about missing targets.

"Node ID already in use" error

Each node's slug must be unique. If you see this error, another node already uses the slug you entered. Choose a different slug for the current node, or rename the conflicting node first.

Changes not showing in the exported game

Export and Preview both auto-save before running, so your latest changes are always included. If a change still doesn't appear, verify you clicked Save Passage (the textarea auto-saves, but the title and slug need explicit saving).

Server won't start

Run ./run_dev.sh from the project root. Ensure Python 3 and the virtual environment are set up. If the port 8005 is in use, edit the script to use a different port. Check the terminal output for error messages.

Tip: The browser console (F12 → Console) is the best place to check for JavaScript errors in the editor. Include screenshots of any errors when reporting bugs.

Key Behaviors & Conventions

Slug Immutability

Every node is assigned a slug (a URL-safe identifier like the_dark_forest) when it's first created. The slug is generated from the node's title at that moment. Renaming the title later does not change the slug automatically. However, you can manually edit the slug in the passage editor's Node ID field. All references (choices, on-enter redirects) are updated automatically when you change a slug. This ensures that connections remain valid even if you reorganize node identities.

Project Warnings & Confirmations

  • Deleting a node — a confirmation dialog appears before removal.
  • Loading a project — a warning appears that unsaved changes will be lost.
  • Export — auto-saves your project before generating the ZIP, so it always reflects your latest work.

Slug Syntax

Slugs are automatically generated using the following rules:

  • Lowercase letters, numbers, and underscores only.
  • Spaces and special characters are replaced with _.
  • Leading/trailing underscores are removed.
  • If a slug already exists, a numeric suffix is added (room_2, room_3, etc.).
